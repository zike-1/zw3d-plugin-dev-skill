# 宿主与代码边界

## SDK证据

使用目标2027安装目录中的SDK头文件和库。对每个新API先核对声明、参数、返回码和内存所有权。将库用于构建，不随插件分发宿主DLL、导入库、可执行文件或授权文件。

DLL必须是x64。静态检查导入符号是否由目标宿主导出，只说明符号存在；不能替代真实加载、回调和模型测试。v1不支持包内私有依赖DLL，私有库须静态链接；仅依赖验证器接受的系统及宿主接口。

## 生命周期

`DllMain`只记录轻量的模块状态。业务初始化、命令注册和资源准备在导出Init中完成。Init失败时释放已经获得的资源，不能留下半注册插件。Exit只释放自己拥有的回调和对象；顺序与获取顺序相反。

框架统一维护功能区，业务DLL不修改共用UI文件、不建立第二个工具箱、不自行卸载其他DLL。函数注册名必须与清单命令ID一致。不要在后台线程直接调用只允许主线程使用的SDK。

SDK回调边界应捕获可预期的C++异常，并给出清楚的失败结果。初始化的异常处理不能保护稍后执行的异步命令；每个异步入口都需要自己的处理路径。

本版本`hotUnload=false`。关闭宿主后或下次启动之前应用待处理操作；运行中禁止通过`FreeLibrary`强行卸载业务DLL。系统API或SDK返回“已请求”也不等于操作完成。

## 资源与数据

资源路径相对于自身DLL或EXE。对中文路径和有空格路径做真实测试；文件系统优先使用Unicode API。SDK只接受窄字符时，按实际编码约定转换并检测字符损失。

设置和日志属于该插件的稳定`id`，不能随着版本更新丢失。普通卸载保留数据。彻底清理只清理框架登记的该插件数据目录，不能递归删除由用户任意输入或简单字符串拼接得到的路径。

设置格式应有自己的版本。迁移前验证旧格式，保存原文件或备份，写入临时文件后替换；未知格式不能静默覆盖。`examples/art-notes/`示范UTF-8便签、格式标记和保留旧文本的迁移。程序更新、设置迁移和安装事务恢复是三个不同过程；本版仍不提供用户主动降级／回退入口。

管理器只读打开不提权，修改时请求必要权限。跨管理员账户授权的“彻底清理”被拒绝；已排队清理遇到不同账户则只卸载程序、保留原账户数据并记录结果。不把管理员账户的设置当作发起用户的设置。本版多账户真实UAC流程仍需独立验收。

DLL通过已加载框架的`ZwPluginHubDataDirectory(id, buffer, count)`查询自己的数据目录，返回0表示成功；缓冲区使用宽字符。EXE读取框架为该进程提供的`ZW_PLUGIN_DATA_DIR`。这两个接口提供路径，由插件按需要创建目录和文件，不要另算宿主路径哈希。

## 模型命令

在命令入口检查当前环境和必要输入。明确取消、失败、部分完成与成功的区别。使用SDK推荐的事务、撤销或恢复方式，使用户可以理解并处理失败。

涉及重生成和保存时，检查每一步返回结果，再决定是否继续；不能仅因为发出保存命令就报告成功。批量功能要处理可预期的提示、记录失败文件，并提供可停止的流程。验证用副本，保留原图证据。

EXE与DLL有不同运行边界。EXE按钮能启动程序，不证明程序能读当前装配、选择集或未保存的模型。确需这些能力时，先确定通信协议、数据所有权和进程退出行为，再实现桥接。
