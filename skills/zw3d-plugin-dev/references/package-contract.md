# 插件包契约 v1

本契约定义框架、打包器和插件共同遵守的格式。适用宿主为中望3D 2027 x64；不能据此推断插件已兼容其他年份。

0.2.3工具包使用框架1.1.3与兼容协议1。保留旧清单必需字段，新增可选`description`、命令`icon`与`tooltip`；支持新增字段不表示旧管理器能生成图标。

从框架1.1.3起，安装EXE的应用图标由首个命令PNG生成，未声明时使用工具箱默认PNG；管理器使用工具箱图标。图标以ICO资源嵌入并保留原PNG像素，不再以工具栏图标存在推定窗口图标存在。源码构建的EXE也生成应用图标资源101，作者为自建窗口设置`WM_SETICON`的大小图标（便签给出完整示例）；源代码资源需保留该组编号。预编译入口不自动改写图标，需由原作者重新构建并增加版本。本轮没有添加独立应用图标清单字段，业务设置格式不变。

## 图标与独立升级

`commands[].icon`是有效载荷内的PNG相对路径，例如`resources/tool.png`；`tooltip`最多240字符，清单`description`最多240字符。图标须为16至256像素的正方形、8位RGB或RGBA、非交错PNG。验证器检查文件存在、完整分块、CRC及解压尺寸。没有提供图标时使用工具箱默认图标。

框架把有效载荷图标投射到自己拥有的命令图标路径，不使用作者提供的全局文件名。每个命令的投射身份由稳定命令ID决定；更新、移除命令或卸载时同步维护，不能覆盖其他插件的资源。

同一插件版本冻结规范化清单和完整文件集合；只改图标或文字也必须增加版本号。主机API兼容检查不属于业务版本内容。安装器升级一个插件时保留其他插件和该插件个人数据。

共用框架以独立版本及协议判断兼容，并检查本地发行文件哈希。协议1的安装器复用兼容的新框架，拒绝损坏或同版本不同内容；较旧框架通过安装事务升级。运行中升级暂存框架及插件，关闭宿主后更新程序取得同一把锁，先提交框架再提交业务版本。若重启过快或更新程序失败，新管理器阻止业务加载、重启更新程序并保留恢复记录；不把仍在加载的DLL直接替换。

0.1.1及更早EXE的逻辑无法追溯改变，需重新生成；旧工具箱首次迁移需关闭中望3D。兼容协议是行为约定，不是哈希签名或发行者认证。破坏兼容的框架必须采用新的协议与明确迁移流程，不能假称兼容。

## 包结构

`.zwplug`是ZIP文件。包内只包含清单、校验表及有效载荷，不包含SDK或宿主程序：

```text
plugin.json
checksums.json
payload/
  ExampleDemo.dll
  resources/...
```

`checksums.json`是`{"相对路径": "小写SHA256"}`对象；路径相对于`payload/`，不加`payload/`前缀。校验表必须完整覆盖所有有效载荷，不允许未声明的文件。清单和校验表由验证器独立验证，哈希仅用于发现损坏和不一致，不证明发布者可信。

所有包路径使用`/`、相对路径和明确的文件名。拒绝绝对路径、盘符、`..`、重复路径以及按Windows规则相等的路径；安装目标不得通过符号链接或重解析点逃逸插件目录。有效载荷必须保留依赖和资源的相对布局。

v1有效载荷最多256个文件、单文件64MiB、合计128MiB，每条相对路径最多180个UTF-8字节。显示名称最多80字符且最多255个UTF-8字节。包只接收常规文件；脚本安装器、符号链接和Windows保留名称不能进入有效载荷。具体准入由同版本验证器执行，不能靠改扩展名绕过。

有效载荷根目录的`descriptor.ini`和`files.txt`由框架保留，不能作为文件或目录使用（大小写不敏感）。资源子目录内的同名文件不会占用框架的根目录位置。

## 清单

```json
{
  "schemaVersion": 1,
  "id": "org.example.demo",
  "name": "示例插件",
  "version": "1.0.0",
  "prefix": "ExampleDemo",
  "type": "dll",
  "host": {
    "product": "ZW3D",
    "versions": [2027],
    "architecture": "x64"
  },
  "entry": "ExampleDemo.dll",
  "commands": [
    {
      "id": "ExampleDemoHello",
      "label": "示例命令",
      "environments": ["top", "part", "assembly", "drawing"]
    }
  ],
  "dataPolicy": "preserve",
  "hotUnload": false
}
```

字段意义：

| 字段 | 要求 |
| --- | --- |
| `schemaVersion` | 固定为整数`1`。不支持的版本拒绝安装。 |
| `id` | 唯一且稳定的小写反向域名身份，至少两段；每段以小写字母开头，其后允许小写字母、数字和内部连字符。不能有下划线、连续或结尾连字符。显示名称改变时仍保留身份。 |
| `name` | 用户看到的插件名称。 |
| `version` | v1使用SemVer的数字三段子集：`主.次.修订`，每段为0–999999且无多余前导零；不接收预发布或构建后缀。升级保持同一`id`。 |
| `prefix` | 2–32字符，以大写ASCII字母开头，其后只有ASCII字母或数字；插件之间唯一，不能以框架保留的`Hub`、`ZwPluginHub`或`IdZpHub`开头（不区分大小写）。 |
| `type` | `dll`或`exe`。 |
| `host` | v1固定产品`ZW3D`、年份`[2027]`、架构`x64`。 |
| `entry` | 入口文件在`payload/`中的相对路径；同一插件的所有命令使用此入口。 |
| `commands` | 1–32条命令声明。`id`以插件`prefix`开头且有非空后缀，稳定、最长64字符；字符限ASCII字母、数字和下划线，按大小写不敏感规则唯一。`label`为按钮文字。 |
| `environments` | v1必须完整列出`top`、`part`、`assembly`、`drawing`，不重复，顺序不限；本版本不支持环境子集或自动按环境隐藏按钮。 |
| `arguments` | 仅EXE命令可用的固定参数字符串；DLL命令不声明。不是Shell命令，不支持把任意用户输入拼接执行。 |
| `dataPolicy` | 固定为`preserve`：普通卸载保留设置和日志。 |
| `hotUnload` | 固定为`false`：不在运行中的宿主卸载DLL。 |

v1使用封闭字段集合，不接收未声明的`author`或其他扩展字段，也没有清单依赖解析、包内私有依赖DLL、按命令不同入口、动态变量参数、环境子集、热卸载和跨年份兼容承诺。私有库须静态链接。同一宿主最多登记128个EXE命令；这是框架总容量，而非单包容量。扩展这些行为须同步修改schema、验证器、框架和测试。模型命令仍应在回调中检查当前上下文；按钮显示不等于当前模型适用。

菜单声明必须显式保证页面、管理组、每插件父组和子控件可见。验收必须读取完整可见性链，并在对应环境真实点开页面看见按钮、点击命令及管理入口；仅子控件标志为1或直接执行命令不能证明菜单可用。0.1.0曾因父组未显示导致空白页，旧界面PASS已撤回，0.1.1已由用户完成限定核心流程验收，0.2.0新图标和界面仍需重新验收。

## 入口与身份

DLL入口文件基名必须与`prefix`完全一致。导出初始化和退出函数：名字为基名加`Init`、`Exit`，例如`ExampleDemo.dll`配合`prefix: "ExampleDemo"`，导出`ExampleDemoInit`、`ExampleDemoExit`。模板负责按SDK约定注册清单中的命令ID；清单按钮应能找到实际回调。

独立EXE接受清单指定的固定参数，由框架启动一次。v1的EXE包不能导入ZW3D进程内API。需要模型上下文、双向通信或进程内API时，不能仅改`type`实现；须设计明确的DLL桥接，并另行验证。

不要把作者名、按钮文字或版本号作为稳定身份。不要共用别人的命令前缀。框架使用`ZwPluginHubPage`和`ZwPluginHubManage`等名称；保留`Hub`、`ZwPluginHub`与`IdZpHub`命名空间，插件不能声明这些名称。

## 框架与插件的位置

逻辑安装布局：

```text
<ZW3D>/apilibs/
  ZwPluginHub.dll
  ZwPluginHub/
    plugins/<id>/<version>/...
    state/...
```

这是框架维护的布局，不是业务代码应写死的路径。插件从自己的模块位置读取资源，用户数据放在框架约定的每插件数据目录；不要写入SDK目录或其他插件目录。

v1当前账户的数据目录为`%LOCALAPPDATA%/ZwPluginHub/<宿主路径标识>/<id>`。框架从规范化后、不区分大小写的宿主路径计算标识，避免同一安装目录因为路径写法不同而得到另一份数据。插件开发应使用工具包提供的统一路径方法，不另写一套哈希算法。

每插件安装EXE携带该插件包和匹配的框架。首次安装建立框架；后续安装检查版本并复用框架。同一身份升级替换自己的活动版本；重复安装不能复制按钮。已有框架不允许静默降级，也不能因为卸载一个插件而删除框架或其他插件。

业务插件打包默认复用`runtime/1.1.4/`中的冻结框架DLL与管理器。协议1安装器检查独立框架版本与文件完整性，复用兼容的新框架，不降级、不覆盖同版本不同内容。维护者修改框架必须增加框架版本，再独立构建、验证和发布；作者不要各自编译同名同版本的框架。

开发候选的`package_existing.py --installer`复用`installer-runtime/1.0.0/SetupTemplate.exe`生成相同协议的安装EXE，只改变资源区及Windows资源更新所需的布局信息，逐字保留非资源节内容。此流程不编译或改写业务DLL/EXE，仍校验原包契约和目标宿主API；同版本内容不同拒绝覆盖。生成安装器为未签名EXE，发行者可在完成校验后另行签名。

安装中的命令身份按ASCII大小写不敏感规则比较；事务文件路径按Windows大小写不敏感规则保持唯一。旧恢复日志如出现同一文件的大小写别名，只有经过校验且完全相同的原始内容可以合并恢复，不一致记录必须停止并保留证据。

管理器提供“修复损坏登记”和“隔离损坏登记”，仅处理活动登记或待处理登记，不重建框架文件和业务文件。修复先备份原记录，再从同身份、匹配原版本的安装描述及完整哈希校验的有效载荷恢复；原版本不可读时，只在安装目录中唯一一个版本完整且兼容的情况下恢复。存在多个历史版本、文件损坏、接口不匹配或身份冲突时停止，不猜最新版本，不改其他插件。

无法确认的活动登记可由用户选择隔离：备份后移出活动登记并重建菜单，安装程序文件与个人数据保留，后续使用原安装包重装。损坏待处理请求无法重建原意，只允许整体备份并隔离；有效待处理请求不会被修复隐式取消，隔离活动登记前须先取消该插件的待处理请求。其他损坏记录仍单独显示，严格安装操作须等相关损坏登记处理完再执行。

宿主运行中，修复或隔离写入独立等待队列，管理器显示等待重启并支持取消。启动握手在正常待处理安装之前应用维护请求，提交时再次检查原记录哈希；记录变化时停止，保留请求供取消，不覆盖新状态。原登记备份、菜单重建与请求移除使用同一事务。备份位于工具箱的`recovery/`目录，不进入用户数据清理范围；备份不是自动恢复入口，重新启用隔离插件使用原安装包。

构建器先暂存并检查插件包与安装EXE的一致性，再发布完整产物；普通构建失败保留上一套完整结果。`--package-only`仅发布包，同时移除这个版本过时的安装EXE、有效载荷副本及报告，不能把单包模式当作完整EXE交付。进程被强制终止或回滚本身被外部占用不属于完整提交承诺；后者保留恢复文件并明确报告路径。

0.1.1及更早安装器属于历史候选：首次迁移需关闭宿主并匹配框架维护者允许的精确发行文件；未知文件拒绝覆盖。它们没有协议1的升级复用逻辑，需要重新生成插件安装器。历史管理器的有界菜单修复不等于当前框架升级规则。
