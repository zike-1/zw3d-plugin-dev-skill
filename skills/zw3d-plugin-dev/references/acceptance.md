# 验收：从包到宿主

验证分三层，按实际执行结果分别报告。`PASS`要求这一层所有适用场景完成；`PARTIAL PASS`列出未完成部分；失败写`FAIL`及可复现原因。

## 一、包和构建

- 按SDK与编译器参数构建；清单身份、命令前缀和实际回调一致。
- 校验完整有效载荷、哈希、x64入口与导入依赖。拒绝坏清单、缺文件、坏哈希、重复身份和路径逃逸。
- 安装EXE包含框架及插件，不依赖开发机私有路径、Python或已存在的构建目录。

## 二、安装事务

在隔离目录依次安装示例A和B，随后升级、重复安装和卸载。检查磁盘状态、清单、按钮声明和保留数据，而不只看退出码。

| 场景 | 应观察到的结果 |
| --- | --- |
| 首次安装A | 一份框架，一份A，只有一个A入口。 |
| 再安装B | 复用框架，A和B都可枚举。 |
| 重复安装或升级A | 稳定身份与按钮不重复，B不改变。 |
| 普通卸载A | A的程序与入口移除，A设置和日志保留，B与框架保留。 |
| 彻底清理A | 仅A登记的数据被删除。 |
| 宿主运行时安装、更新、卸载 | 当前活动版本不被覆盖，显示等待重启；待处理记录可恢复。 |
| 下一次启动 | 在业务DLL加载前取得安装锁、恢复未完成事务并提交待处理操作；握手失败或超时则该会话不加载业务插件。 |
| 文件锁定、坏包或中断 | 不出现半安装；可恢复原状态，其他插件不改变。 |
| 修复损坏活动登记 | 先备份，校验身份、匹配版本、文件哈希和接口，再恢复；其他插件及个人数据不改变。 |
| 无法确认版本或业务文件损坏 | 拒绝猜测恢复，不修改现场；可隔离后用原安装包重装。 |
| 隔离损坏登记／请求 | 完整备份原记录／请求文件，重建菜单，程序与个人数据保留。 |
| 运行中维护或请求后记录变化 | 等待重启、可取消；启动先维护后安装，旧请求不得覆盖已变化记录。 |

测试待处理操作应包含同一插件的连续请求，并检查最终结果及事务记录。框架自身更新也需要验证，不能用业务插件的重启测试替代。

0.2.1还检查：重复安装不改变菜单顺序及文件内容；同版本修改清单或文件集合被拒绝；仅A更新图标后B及其设置不变；坏登记单独显示且正常插件仍加载；切换安装目录立即使旧选择失效；取消待处理请求保留活动版本；设置迁移保留原文件。框架升级包含旧候选离线迁移、运行中暂存、关闭后提交，以及协议1旧安装器复用兼容的新版本。

模拟宿主与模拟后续框架只验证进程、文件和协议分支，不证明真实2027绘制或另一真实发行版本兼容。图标显示、便签交互、各模型环境和多账户提权必须分别记录实测结果。

## 三、真实宿主

用目标2027的真实进程和模型副本完成：

1. A、B在同一个“扩展工具”功能区。在正常显示的宿主窗口中先点开页面看见按钮，再核对页面、每个父组和子控件的SDK状态并点击按钮；管理入口必须实际打开管理器，列表正确显示插件和活动/待处理状态。未选中页面或隐藏窗口的分组查询不能直接作为显示验收；子控件标志为1也不证明按钮已绘制。

图标还须检查安装EXE文件、管理窗口及业务自建窗口的标题栏／任务栏。便签须实际键入后按Esc，分别确认保存、放弃和取消的结果；不能将只点保存按钮或文件读写自检当作键盘交互验收。
2. v1每个命令在首页、零件、装配、工程图四类环境分别完成上述检查；通过直接命令执行不能代替实际按钮点击。命令执行检查当前上下文，不适用时明确提示，不修改模型。后续环境子集能力须单独通过宿主事件与完整界面验收后再开放。
3. 功能按需求产生结果；需要保存的功能重新打开产物核验，原图保持约定状态。
4. 从管理器移除A后重新启动，B仍能运行；普通卸载与彻底清理的区别可观察。
5. 中文路径、有空格路径、第二个正常宿主安装目录可以使用；卸载仅影响选定的宿主。

`tests/test_installed_host.py`只在完整源码仓库中提供，用于已有安装的SDK检查；独立技能ZIP不含此脚本。单独使用技能时，按本节五步人工验收，使用随附的包验证器和`tools/inspect_installer.py`检查交付物；没有SDK探针时将该项标为未验证，不编造不存在的工具。`--interactive`显示自己的空白会话，等待人工选中插件页后再读取父组状态；探针不代替按钮点击与管理器交互。0.1.0曾出现用户实际空白页，旧界面PASS已撤回。修复须保留实际选中页面的显示和点击证据，不能沿用旧通过结论。

如果没有目标宿主、无法操控界面或测试被对话框阻塞，记录已运行的静态检查与事务测试，将真实宿主交互部分写为未验证。不能将导入符号检查、模拟进程、SDK可见标志或框架初始化日志写成完整界面验收。

保留简短报告：产物版本和哈希、环境、执行场景、结果、原始证据路径，以及尚未覆盖的功能。让下一位作者知道哪些结论能够复用，哪些需要重测。

构建失败须比较上一套包、安装器和报告保持一致；图标准入须拒绝非法行滤波类型。更新命令大小写、文件占用后的完整回滚、旧别名日志恢复、坏活动登记与有效待更新记录共存、正常DLL在其他登记损坏时仍可查询数据目录，均属于维护者的回归检查。
