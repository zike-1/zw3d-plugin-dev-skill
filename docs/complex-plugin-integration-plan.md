# 复杂插件入口与开发环境：下一版设计边界

> 开发分支审查材料；不是已发布的 0.2.4 技能能力，也不是中望3D 2027 真实宿主验收记录。

## 先确定「命令」的层次

- **内部功能**：插件源代码中用于实现功能的函数、算法和处理流程，数量不受 Hub 清单限制。
- **原生 SDK 命令**：由业务 DLL 通过 SDK 注册的命令。DLL 可以有多个，不能据此推定每个都要成为 Hub 菜单按钮。
- **Hub 声明的入口**：`plugin.json.commands` 中声明的项目，由 Hub 生成图标与功能区入口，**当前每个包最多 32 项**。
- **按钮/菜单/子命令**：原生 UI 如何呈现这些功能，可能是按钮、下拉菜单、对话框、右键菜单或自定义面板，并不与 SDK 命令一一对应。

因此「68 个功能/命令」不能自动推导为「68 个 Hub 按钮」，更不能因此强制拆成三个互不关联的安装包。

## 保持统一顶层界面

- Hub 统一管理 `扩展工具` 顶层功能区、管理入口和插件安装状态。
- 业务插件默认不应新增自己的顶层功能区；优先从 Hub 暴露少量可执行主入口。
- 复杂插件可以由一个主入口打开自己的操作面板；窗口内的 68 项功能不要求各自在 Hub 清单重复登记。
- 如果现有插件自带 `.zcui` 创建顶层功能区，**加载 DLL 不会自动把旧菜单移入 Hub**。应先确认实际资源及宿主行为，再决定是否进行原生菜单迁移。
- 对「多个原生 RibbonGroup/ControlMenu 全部放入 Hub」的诉求，属于另一项功能：先以真实插件取得宿主证据，再设计可选 UI 接入配置，不能假定 v1 已提供。

## 环境显示不能靠简单删除清单字段

当前 v1 清单每个入口都要求包含 `top,part,assembly,drawing` 四种环境，
安装器将同一个 `ZwPluginHubPage` 插入多个宿主环境。
插件业务回调应当自行判断当前零件、装配及图纸是否适用。

支持 **按命令独立配置可见环境** 需要同步修改：
1. `schema/plugin.schema.json`、`tools/package_lib.py`、`framework/common.h` 对子集的校验；
2. `framework/setup.cpp` 生成的页面与环境布局，避免仅修改清单但各环境继续共用一组可见按钮；
3. 安装事务、升级、卸载、损坏登记恢复及旧包兼容；
4. 在正式 2027 宿主的首页、零件、装配和工程图中实际点开页面、检查父组及按钮可见性并点击命令。

在完整实现前不应放宽 `environments` 的限制，以免清单宣称某环境隐藏、实际仍然出现按钮。

## 无需重复编译的预编译插件打包（开发分支）

准备合法来源的业务 `payload/`（已有 DLL/EXE、必需资源）和符合 v1 的 `plugin.json`。例如：

```powershell
python tools/package_existing.py work/my-prebuilt-plugin --out dist
python tools/validate_package.py dist/org.example.my-plugin-1.0.0.zwplug
```

若提供 `--sdk "ZW3D2027安装目录"`，构建器会额外核对插件导入的宿主 API 是否存在。
**此流程不需要 MinGW、不调用编译器、不重新编译既有业务 DLL**，但仍需 Python 3 执行打包与校验。

安全边界与现有 `package_lib` 一致：校验 x64 PE、要求 DLL 的 `prefix + Init/Exit` 导出；
拒绝未满足依赖约束的插件、未经支持的私有 DLL、无效资源和 SDK 宿主二进制再分发。
「不用重新编译业务文件」不代表「任意旧 DLL 可以无修改直接接入」。

**重要：这个命令仅生成独立 `.zwplug`，不生成用户双击安装的 EXE。当前 HubManager 不能直接导入这个包。**
最终安装交付仍要由现有 Windows 构建器生成安装 EXE。
要真正免编译完成安装交付，需要后续单独开发并验收离线包导入/复用签名可信的通用安装器等方案；
不得把目前包创建能力宣传为已经解决了安装器构建依赖。

## 对 68 命令插件的最小实证

1. 先从 DLL 初始化源码或官方 SDK 注册日志确认：68 是内部处理函数、SDK 注册命令，还是独立菜单入口；
2. 确认一个主命令能打开原插件的完整业务界面，`plugin.json` 暴露该主命令即可；
3. 以单个插件包安装，在 `扩展工具` 下只有一组/少量入口，不增加独立顶层选项卡；
4. 验证全部原有功能与模型事务，切换首页/零件/装配/工程图，卸载/重装后其他插件不受影响；
5. 如果必须原生并列展示全部独立命令，再收集 Ribbon 布局实例来确定是否需要超过 32 个清单入口。

## 交付与版本

此开发分支不修改 `runtime/1.1.4` 二进制、不覆写 0.2.4 发布 ZIP，也不声称已通过真实 GUI 验收。
验证通过后如决定改变框架协议/UI，须单独升级框架版本，重新打包与发布技能，
并证明旧插件的安装/卸载和版本兼容行为未发生回归。
