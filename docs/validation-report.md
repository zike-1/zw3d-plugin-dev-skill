# 0.1.1 修复候选验证报告

验证日期：2026-10-02。当前结论：**PASS（本机已验收的核心流程：显示、点击、管理列表、单独卸载及重启后保留其他插件）**。其他环境、跨电脑与完整版本升级仍未验收，不代表全场景正式发布通过。

0.1.0实际界面验收为FAIL：用户安装两个示例后看到空白页。此前“首页功能区通过”的表述已撤回。旧测试只查询页面和子控件，并直接执行命令，未点击页面、检查父组与实际画面。

发现两层配置问题：生成的插件分组漏写`visible="true"`；用户CustomRole中15个环境另有旧分组的`visible="false"`及旧面板下控件的覆盖。0.1.1显式声明分组可见，将内部组改为`HubManagementGroup`、`HubPlugin_<prefix>`，面板改为`HubManagementCommands`、`HubCommands_<prefix>`，避开旧覆盖。页面、Action和命令身份保持不变，不清空用户快捷键或其他界面设置。

最终修复已安装到本机2027。仅更新己方管理器与菜单；84个其余插件/资源文件哈希对应，其他页面节点和两个业务有效载荷保持不变。旧管理器只在目标关闭、框架DLL一致且SHA精确匹配时允许一次迁移；未知管理器和运行中的迁移被拒绝且无文件变化。

用户在正常2027中选中右侧“小插件”页，回复“**三个按钮都看到了**”，确认“管理插件、优雅问候、示例便签”实际显示。随后分别点击三个按钮，回复“**三个都正常**”，确认两个示例弹出提示，管理器打开并列出两个插件。原空白页故障及首页三个入口已完成用户实测；两个示例另有SDK直接命令成功日志。

随后按“在管理器卸载优雅问候，重启2027，确认该入口消失而示例便签仍可使用”的步骤验收，用户回复“**验收通过**”。本机单独卸载与重启后的插件共存通过；未据此扩大到其他未测试场景。

实机探针曾在未经人工选中插件页的隐藏会话中读取分组值0，系统首页对照为1。这不等价于页面选中后的显示状态：最终同一配置已由用户确认显示。测试现在保存父组、子控件与缺失对象负对照；`--interactive`显示自己的空白会话，等待人工选中插件页后再检查父组。自动隐藏会话只断言父组存在和字段有效，不把0直接判为显示故障，也不把子控件的1判为绘制通过。Computer Use因本机sandbox helper锁错误无法启动，真实点击由用户验收。
