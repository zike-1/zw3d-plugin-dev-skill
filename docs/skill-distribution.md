# 技能发布与同步

仓库源码与单独安装的技能必须使用同一套模板、框架和验证器。

源码模式中，`skills/zw3d-plugin-dev/SKILL.md`引用仓库的`tools/`和`templates/`。单独发布技能时，通过同步脚本将当前的`framework/`、`tools/`、`templates/`与schema复制到技能的`assets/kit/`，并将对应候选的自编框架DLL与管理器放在`assets/kit/runtime/1.1.3/`；然后校验技能、构建示例，并在发布清单中记录这些文件的哈希。

同步是构建动作，不是手工维护第二份代码。修改真实模板或验证器后，应重新生成技能包；不要直接修补生成目录。SDK、宿主程序、用户图纸、原始第三方安装器、开发机缓存和密钥均不进入技能包。

发布包应该让作者只需提供目标SDK和编译器路径，就能创建示例、构建并生成独立安装EXE。框架版本变化时，先验证现有安装和两个新插件的共存，再同步发布技能包。仅发布技能文字不会提供自动安装、共用菜单或管理器能力。

当前0.2.3修复版已获用户确认通过，使用冻结框架1.1.3。各轮的实际范围见验证报告；新修改仍须按范围回归。发布前真实点开页面看到并点击按钮；SDK标志和直接执行命令不能代替画面。不同版本与不同环境的验收范围分别记录。

业务插件构建默认使用冻结的运行时发行物；`--build-framework`只用于框架维护。源码开发阶段可以使用本机`dist/framework`缓存，发布后的插件作者不依赖维护者机器上的缓存。

维护者确认运行时和示例验收后，在仓库根目录运行：

```powershell
python -X utf8 release/pack_skill.py
```

0.2.3的冻结产物为`skills/zw3d-plugin-dev/assets/kit/`及`release/zw3d-plugin-dev-0.2.3.zip`；ZIP哈希见0.2.3验证报告。ZIP以技能目录为根，可作为完整技能包安装。`kit-sha256.json`记录生成文件哈希，旁边的发布记录保存ZIP哈希；固定ZIP时间戳便于比较重复构建。

首次GitHub发行运行`python -X utf8 release/pack_github.py`，生成不同文件名的`zw3d-plugin-dev-0.2.3-github.zip`和`ZW3D2027-examples-0.2.3.zip`。它验证原冻结ZIP及安装器，加入LICENSE和第三方声明，不改写已验收的技能文件、运行时或安装器；不覆盖原发行物，也不执行GitHub上传。公开发行物哈希与下载列表见`docs/release-0.2.3.md`及`SHA256SUMS-0.2.3.txt`。

0.2.3使用独立框架版本1.1.3和兼容协议1。旧候选首次离线迁移、新协议版本的暂存更新及兼容复用分别测试；更早EXE无法追溯修复，需要重新生成。协议与哈希检查不等于发行者认证。真实宿主及跨账户验收范围见本轮验证报告。

生成目录带ownership标记。脚本只替换完整且未被修改的己方生成目录；已有未知文件、目录或人工修改时拒绝覆盖。请把需要保留的内容移到源码位置，不能直接编辑生成的kit。脚本验证路径、冻结运行时校验表和发布记录，不复制SDK、密钥、缓存或测试日志，也不执行GitHub上传。

发布组装测试用独立合成fixture，运行`python -X utf8 -m unittest discover -s release -p test_pack_skill.py -v`。它证明打包和覆盖保护行为，不替代运行时或真实宿主验收。

`quick_validate.py`通过只能证明技能结构符合格式。发布验收仍依赖[包、事务和真实宿主测试](../skills/zw3d-plugin-dev/references/acceptance.md)。
